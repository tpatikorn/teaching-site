4.1 Function Call Stack Visualizer

Understand execution flow, stack frame pushing/popping, and recursive call footprints in memory.

Activation Records

Each time a function is called, the system creates a stack frame (activation record) containing its parameters, local variables, and return address. When a function finishes, its frame is immediately popped off. Observe recursion or nested calls below.

1. Prototypes vs. Definitions

• Declaration (Prototype): Informs the compiler about the function's name, arguments list, and return type before it is called (e.g. int add(int, int);).
• Definition: Contains the actual execution code blocks (body) of the function.

2. Call-by-Value vs. Reference

• Call-by-Value: C's default passing mechanism. Arguments are copied into parameter variables. Modifications inside the function do not affect the caller's variables.
• Call-by-Reference: Achieved in C by passing pointers (address variables), allowing the function to dereference and modify the caller's memory directly.

3. Recursion & Stack Overflow

A function that calls itself is recursive. It must have a base case to terminate. Without it, successive recursive calls will allocate infinite stack frames, leading to a program crash known as Stack Overflow.
